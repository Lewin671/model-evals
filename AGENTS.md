# Working on this benchmark

Use Python standard library only. Never publish credentials, raw CLI transcripts,
session IDs, home paths or personal configuration. Results must distinguish model
failures from infrastructure failures. Freeze generators and graders before paid
runs; never tune a grader to favor a model. Keep initial goals, inputs and world
seeds identical across models; interactive observations may diverge with actions.
Do not claim statistical significance from one small paired run.

English is the default language for the README, documentation and public reports.
Present this as model capability evaluation; Command Code and Codex are harnesses.
Every comparison must include model ID, harness, explicit reasoning effort and
whether identity/effort were observed or only configured. Publish measured results
with per-task evidence; never put illustrative scores in a real leaderboard.

The current scope is general coding, everyday tasks, browser workflow reasoning and
desktop workflow reasoning. Do not include security in new model campaigns. Keep
legacy results archived. Give each of the four domains equal aggregate weight.
Label structured UI snapshots as simulation: they do not establish visual perception,
actual tool execution, or closed-loop recovery. Accept equivalent valid actions and plans.

The prototype suites did not establish useful capability discrimination. Do not use
toy one-step snapshots, hinted next actions, or response-format failures as the main
evidence of model ability. Separate semantic task outcomes from interface compliance.
Before another full paid campaign, require reference traces, failing simple baselines,
predeclared difficulty tiers and a small calibration pilot. Count model requests and
tokens, not just CLI sessions, when setting the budget. Publish ceiling/floor effects;
never manufacture a ranking by selecting favorable tasks after seeing results.
